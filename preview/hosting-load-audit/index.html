האם המפה תחזיק מעמד כשיבואו הרבה מבקרים?

בקצרה: עד כ-3,000 כניסות ביום הכול בסדר. סביב 5,000 ביום נחצה את המכסה המומלצת של GitHub, ואז כדאי להעביר ל-Cloudflare גם את קובצי האתר עצמו. מצד Cloudflare אין בעיה גם ב-5,000.

שלושה תרחישים

הכוונה לטעינות של האתר ביום, בממוצע על פני חודש, כשכל מבקר פותח אותו לראשונה (בלי שמירה בדפדפן). אלה חישובים על בסיס מדידה חיה, לא בדיקת לחץ.

הכול בסדר

GitHub משתמש בכ-31% מהמכסה שלו, ו-Cloudflare בפחות מ-2%. אין צורך לעשות כלום.

הכול בסדר

GitHub משתמש בכ-63% מהמכסה שלו, ו-Cloudflare בכ-3%. עדיין יש מרווח, אבל כדאי להתחיל לעקוב.

5,000 טעינות ביום

חורגים ב-GitHub

GitHub מגיע לכ-157% מהמכסה המומלצת. זו מכסה רכה, כלומר האתר לא נופל ברגע שחוצים אותה, אבל GitHub עלול לפנות אלינו או להאט את האתר.

Cloudflare נשאר רגוע: כ-7.5% מהכלול בתוכנית (עד 15% אם כולם טוענים את המפה המלאה).

מה עושים: מעבירים גם את קובצי האתר עצמו ל-Cloudflare, ואז GitHub כבר לא נושא את העומס.

הנקודה שבה GitHub מגיע למכסה: בערך 3,200 טעינות ביום. מבקרים שחוזרים לאתר טוענים פחות, ולכן בפועל יש עוד מרווח. כל תנועה אחרת באתר של GitHub צורכת מאותה מכסה.

מה זה lite?

lite הוא מצב מפה קל. במקום לטעון את כל נתוני המפה מראש, הוא טוען רק את הבסיס, והמפה עולה מהר יותר. נתוני הפירוט של עיר נטענים רק כשנכנסים אליה.

כשמבקר ב-lite נכנס לעיר בפעם הראשונה, נטענים עוד כ-3.2 MB (5 קבצים). לכן lite חוסך בעיקר למי שרק מסתכל על המפה הכללית.

ההבדל בין שני המצבים נוגע ל-Cloudflare בלבד. ל-GitHub אין הבדל: בשני המצבים הוא שולח את אותו האתר (כ-1 MB).

איך זה בנוי

GitHub Pagesשולח את האתר עצמו (העמוד, הקוד והעיצוב), כ-1 MB לכל מבקר חדש. יש לו מכסה חודשית מומלצת של 100 GB.
Cloudflare (בתשלום)שולח את נתוני המפה. כלולים בתוכנית 10 מיליון בקשות בחודש, ואין תשלום נוסף על נפח.

הנתונים הוצאו מ-GitHub אל Cloudflare עוד לפני הבדיקה, בשני הכתובות של האתר (github.io ו-nirsmilga.com).
